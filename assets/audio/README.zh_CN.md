# 恐龙护照开发语音

当前 [dinobook40](dinobook40/) 目录包含 40 种恐龙的 202 段离线普通话语音。
它们使用 macOS 普通系统合成语音 `Tingting`（`zh_CN`），语速为 155。
这些是开发语音，读音与演绎尚未经过设备验收。生成过程只保存文件，
从不向扬声器播放。仓库没有附带 Apple 语音模型或系统软件包，也没有
声明定制配音的再分发许可。此前 [dinobook](dinobook/) 的 42 段版本保留
作为源文件历史，不是当前固件资源。

[manifest](dinobook40/manifest.json) 记录每段朗读原文、声音来源、PCM
格式、片段 ID、时长、采样数、资源绝对偏移及 SHA-256 哈希。
恐龙知识和观察题依据[目录](../data/dinosaurs.json)中链接的官方博物馆
和研究来源改写。显示知识每条为 25–40 个汉字；`spoken_facts` 是描述同一
观察内容的独立 16–20 字摘要。欢迎语和发现提示由应用作者编写。

| 片段 ID | 内容 |
| --- | --- |
| 0–39 | 按目录顺序排列的恐龙名字 |
| 40–119 | 每种两条朗读知识：`40 + dinosaur * 2 + fact` |
| 120–159 | 问题及两个带编号的选项 |
| 160–199 | 答错后的观察提示 |
| 200 | 发现恐龙和留下足迹的提示 |
| 201 | 欢迎语 |

## 源文件与资源格式

保留的每个 WAV 都是 8 kHz、有符号 16 位小端、单声道 PCM。
此格式缩小语音资源体积，同时保持朗读语速。生成器将峰值归一化到约
12,000，在检测到的语音前后保留 20 ms 余量，再增加开头 100 ms、结尾
180 ms 静音。不保留临时 AIFF 中间文件；WAV 可用于后续编辑和重新编码，
无需再次合成。

`dinobook40/audio.bin` 是外部音频分区镜像。其 64 字节身份头
包含八字节标识（`DINOA40` 后跟零）、小端 32 位镜像总大小、32 字节载荷
SHA-256，以及 20 个预留零字节。所有描述符偏移都是此文件的绝对位置，
不小于 64。完全相同的编码流共享偏移。[C 文件](../../main/dino_audio_assets.c)
只包含预期身份头和 202 个描述符，不嵌入压缩音频载荷。当前镜像大小为 3,200,798 字节，包含约 800.17 秒语音；精确资源大小和
哈希见 manifest 与[生成头文件](../../main/dino_audio_assets.h)。

每段语音都是连续的 4 位 IMA ADPCM 流，先低半字节，初始预测值和索引
均为零。片段没有 WAV 容器或分块头。第一个半字节编码第一个 PCM 采样。
采样数为奇数时，多编码一个零 PCM 采样补齐最后一个字节；描述符的
`samples` 不包含补齐采样。解码以完整字节分段并保留解码状态，播放在
指定的真实采样数处结束。

固件启动时，在播放前将分区身份头与预期头比较。这可以识别与当前构建
不匹配的资源，但不会在设备上计算整个载荷哈希。离线验证器检查完整
镜像哈希和每个片段。流式读取和小 PCM 缓冲避免将整段语音载入内存。

## 重新生成与验证

需要 Python 3.9 或更高版本及宿主 C 编译器。语音合成还需要 macOS 的
`say` 和 `afconvert`；验证与 WAV 重编码仅使用 Python 标准库和编译器。
Python 3.13 无需 `audioop` 即可使用。

```bash
python3 tools/generate_dino_catalog.py --verify
python3 tools/generate_dino_audio.py
python3 tools/generate_dino_audio.py --from-wav
python3 tools/generate_dino_audio.py --verify
```

生成使用 `say -v Tingting -r 155`，再执行
`afconvert -f WAVE -d LEI16@8000 -c 1`。只有文字、声音、语速、采样率及
已保存的文件哈希匹配时，才复用已有 WAV。`generation_progress.json`
保存每段完成后的文字与文件哈希，支持失败后的续生成；单次 `say` 超时
30 秒时最多重试三次。`--from-wav` 根据保留的 WAV
重建镜像、描述符和 manifest。`--verify` 不合成也不修改素材：它检查目录
文字、源文件哈希、PCM 格式、精确采样数、重新编码、载荷与身份头完整性、
去重偏移、生成 C 与头文件，以及实际 C 解码器的每个输出采样。
独立标准库 IMA 参考实现曾与 Python 3.9 `audioop` 对比，覆盖旧版 42 个
WAV 及固定的正负数、奇数长度和解码向量。

[解码器宿主测试](../../tests/test_dino_adpcm.c)覆盖参考向量、半字节顺序、
饱和限制、无效状态和参数、容量不足、超大输入，以及分段解码一致性。
固件和音频资源应通过仓库打包流程一同交付；只替换应用可能留下不匹配
的旧资源。

## 待验收事项

宿主检查证明编解码及文件一致性，不能证明读音或扬声器质量。需要在真实
设备上检查所有恐龙名字、生僻词、朗读选项顺序、清晰度、音量、削波和
播放取消。尤其注意 40 个名字中的生僻字及较长名字。设备播放和读音验收
仍待进行。

## 公开源码与本地录音

公开 GitHub 源码排除两代 Tingting WAV/ADPCM 录音、外部 `audio.bin` 和本地合成检查点。文件保留在开发者工作目录；文字、来源、哈希和描述符继续纳入版本管理。[Apple macOS Sequoia 许可第 2F 节](https://www.apple.com/legal/sla/docs/macOSSequoia.pdf)限制系统语音的公开分享。录音以及包含它们的固件、交付 ZIP 仅保留为本地个人开发制品。

干净检出可在没有语音资源时构建。CMake 明确报告缺少语音且不注册音频镜像；运行时拒绝不存在或不匹配的资源，文字、题目、足迹和动作页仍可使用。语音镜像及 WAV 均不存在时，静态门禁明确报告 `Audio asset checks: NOT RUN`；部分本地资源仍会验证失败。完整本地资源继续执行全部检查，这不授予再分发权利。

macOS 生成器仅供本地个人使用。公开语音需要另行取得可再分发的录音、更新来源并重新生成描述符，通过完整资源校验后再纳入镜像。公开语音及实机读音尚待完成。历史交付工具需要完整本地语音资源，不能用于公开静音版本打包。详见 [GitHub 验证](../../docs/dinobook-github.zh_CN.md)。
